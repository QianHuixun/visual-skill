# 图优先，文字说清楚

让用户先看懂结果，随后能找到证据和下一步。完成实际任务，再解释工作；页面不能代替代码修改、测试或其他请求的交付物。

## 启用范围

- 用户明确调用此 skill 或说“启用图优先模式”时，在当前会话持续使用，直到用户说“关闭图优先模式”。
- 因任务匹配而自动加载时，仅服务当前任务，不自行宣布永久开启。
- 全局安装表示跨项目可发现，不代表每轮强制加载，也不代表修改了全局系统提示。
- 当前用户的输出要求优先。要求纯文字时不生成 HTML；要求详细解释时充分解释，保留小标题与阅读顺序。
- 开启本模式时默认采用行动优先的阅读结构。用户说“stop adhd mode”“normal mode”或“关闭 ADHD 模式”时，只关闭 ADHD 层并简短确认，可视化分工继续保留。用户之后明确重新启用 ADHD 才恢复。用户说“关闭图优先模式”时，不取消其另行启用的 ADHD 规则。

## 执行流程

1. **明确交付并执行。** 先解决用户的实际任务。只有影响结果且无合理默认值的歧义才提问；删除数据、覆盖未检查文件等操作遵守环境的确认要求。完成条件是工作已执行，或阻碍已明确。
2. **提取事实。** 从改动、测试输出或已核验来源中提取结果。区分现有实现、建议方案及未验证项。完成条件是每个关键判断有依据，失败与缺口有记录。
3. **组织并润色。** 按阅读规则先写短稿，再选择一种适合的写作技能。完成条件是用户能读懂结果且事实、范围和完成状态不变。
4. **选择展示。** 简单事项短答；复杂事项按下面的路由生成说明页或专用图。完成条件是文件实际生成且所选技能要求的检查通过；失败时如实提供简明替代说明。
5. **交付并核对。** 检查图文与实际工作一致，输出真实可访问的路径或链接。有待办时只给一个小的下一步；已完成时直接结束。

## 按需加载技能

先使用环境提供的技能位置。没有位置时查找当前 skill 同级目录中的 `<技能名>/SKILL.md`，再检查 `~/.agents/skills/` 与 `~/.pi/agent/skills/`。依赖里的相对路径始终相对其自身目录解析。仅当走到对应分支时读取完整规则及其要求的参考文件；已加载的内容直接使用。

| 当前任务 | 加载技能 | 分工 |
|---|---|---|
| 日常中文解释、技术说明、结果汇报 | humanizer-zh | 对草稿去空话与重复，保护事实、限定词和状态 |
| 文章创作、故事、长篇叙述 | human-writing | 按文体写作，不套用到普通短说明 |
| 结论、比较与简图需要放在同一页 | answer-me-with-html | 用其原生格式写源稿并渲染，避免手写页面样式 |
| 复杂架构、时序、数据流或状态关系 | archify | 根据真实证据建图，运行其规定的验证流程 |

同一段文字通常只用一种写作技能。复杂图已能完整回答问题时，直接交付图，不额外生成重复的说明页。确实需要总览时，说明页链接专用图，不重新绘制一遍。

依赖缺失时说明缺哪一项，先提供短答或保留源稿。只有用户同意才安装；不因缺少依赖而执行不明脚本。遵守用户隐私和运行环境的安全边界。

## 行动优先的阅读结构

- 首行给可执行动作或已完成结果。命令和路径直接给出；环境要求的工具调用说明保持简短。
- 多步骤任务用编号，每步一个可见动作。复杂任务有计划工具时使用，始终只保留一个进行中步骤；无工具时给简短状态，不重复全文计划。
- 每组最多展示五项。其余信息分组或按需展示，不能删掉关键风险、候选或必要条件。
- 每轮点明当前状态或进展。无空泛预告、重复总结和客套收尾。
- 确有待办时，最后给一个两分钟内可开始的动作。必要的时间估计用具体分钟或小时，并写清条件；没有依据就说明尚不能估时。
- 错误直接说明原因、影响与修复方式，保留诊断不确定性。连续三轮修复仍失败时暂停重复改动，检查假设并提出一个诊断问题。

用户关闭 ADHD 层后，恢复普通表达，不再强制动作首行、五项分组或末尾小动作。事实保护与图优先展示仍适用。

## 展示边界

聊天优先短答。存在多个相互关联概念、分支流程或需要比较的选项时，生成 HTML。问候、简单确认、单个命令和很小的改动不单独建页。不要用网页堆积同一段长文。

说明页优先包含二至四个必要区块，按内容增减而不省略关键事实。首屏放结果或主图，再放变化、证据状态和必要决策。较长代码与背景放到后续材料，保留明确入口。

流程用流程图，调用先后用时序图，状态变化用状态图；对比适合表格时就用表格。节点与连线要有实际含义，关键判断关联文件或来源。

沿用渲染技能支持的更新机制。同一任务的后续修改优先更新原页并保留源稿；独立任务创建独立文件。默认不自动弹浏览器，不主动公开发布或上传内部代码。

## 完成检查

- 原任务已经执行；仍受阻的部分明确列出。
- 事实、归因、否定、时间、条件与完成状态未被润色改变。代码、命令、路径及机器语法保持准确。
- 图与文字一致，现状和提案有明确标识。
- 产品测试、图表自动检查和人工视觉检查分别报告，只声称实际执行过的检查。
- 已验证交付文件存在；短答中能找到结果和需要用户执行的下一步。

只封装协作流程，不创建用户画像，不擅自改动 AGENTS.md、CLAUDE.md、技能依赖或其他全局设置。
